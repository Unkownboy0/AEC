# CAMPUSOS — FILE & DOCUMENT LIFECYCLE AUDIT

This audit inspects all 18 file and document types across the GEETORUS CampusOS enterprise suite to trace their models, storage keys, generators, endpoints, authorization models, soft-delete/trash mechanisms, content generation sources, and root causes of reported failures.

## 2. Root Cause Summary of Reported Production Issues

1. **Blank / No-Data PDF Downloads**:
   - `student-fee.controller.ts`: Called `createFeeReceipt(payment).pipe(res)` where `createFeeReceipt` never called `doc.end()`. The stream hung or wrote 0 bytes.
   - `idcard.pdf.ts` & `enterprise.controller.ts`: Streamed directly without validating that the generated buffer length was greater than 0, causing premature disconnection on slow networks or image loading hiccups.
   - Missing response headers: `Content-Length`, `X-Content-Type-Options: nosniff`, and `Cache-Control: private, no-store, max-age=0, must-revalidate`.
   - Client response parsing: When an error occurred, the client received a JSON error (e.g. 401/404/500) but in some paths converted it into a `Blob([res.data], { type: 'application/pdf' })` and downloaded the JSON error text as a corrupted PDF!
2. **Broken File Delete / Foreign Key Crashes**:
   - `FilesController.delete` attempted immediate physical `fs.unlinkSync` and `prisma.mediaFile.delete`, which caused foreign key constraint violations whenever the media file was referenced by `User`, `DigitalIdCard`, `CampusDriveItem`, `GovernedFileReference`, or `Attachment`.
   - Normal file delete was missing the Trash (soft-delete) phase with `isTrashed: true`, `trashedAt`, `deletedBy`.
3. **Campus Workspace Drive & Document Trash / Restore Gaps**:
   - `GovernedFileService.listDriveItems` with `includeTrashed: true` defaulted `parentId: null`, causing items trashed from inside folders to be invisible in the Trash view.
   - `WorkspaceDocumentService.listDocuments` lacked default exclusion of `ARCHIVED` / `TRASHED` documents, so deleted docs reappeared in the active list.
   - Document sharing saved `targetUsers` in the database but failed to emit `DOCUMENT_SHARED` notifications or update recipient badges.
